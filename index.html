Logic Explanation

My website uses the lootItems array as main storage for loot data, and partySize keeps the current party number. In Phase 3 this data also gets saved, so refreshing the page does not just delete everything. The saveState function saves one object with loot and partySize inside localStorage.

When the page loads up the restoreState checks if saved data exists. If it does it reads saved information, restores party size back into the input and loops through saved loot items. It also checks so items in the save storage array have name, value and quantity before it gets pushed back into lootItems.

JSON.stringify is used because localStorage can only save text, so the object has to become a string. JSON.parse is used when the page opens again to turn that string back into usable javascript data. The parse part is inside try and catch so if saved data is broken the app goes back to default state instead of crashing.

For debugging I would put a breakpoint in restoreState after JSON.parse but before updateUI. At that moment I can look at parsed saved object to check what loot was restored and step through the loop that validates every item. This shows if the state is ready before the interface is rendered.

The Reset All button is added because saved data now stays after refresh so it allows user to start over on purpose. It clears lootItems, puts party size back to 1, removes saved localStorage object, and then updateUI shows empty state again. This phase uses HTML, CSS and JavaScript together with arrays, objects, loops, validation, JSON and localStorage to make the app work more like a real web application.
